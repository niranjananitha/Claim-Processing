# Claims Management Backend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a secure, role-based FastAPI + MySQL backend that serves the existing Next.js claims UI, with the project's real XGBoost and MobileNetV2 models wired in as decision support.

**Architecture:** Layered FastAPI app under `backend/` (routes → schemas → services → models, with core/database/dependencies). SQLAlchemy ORM + Alembic migrations against the running local MySQL `claims_database`. JWT access tokens (short TTL, returned in body) + rotating refresh tokens in an httpOnly cookie. ML models loaded lazily by a modular `ml_service` that degrades to an OFFLINE status when a model cannot load.

**Tech Stack:** Python 3.13, FastAPI, Uvicorn, SQLAlchemy 2.x, Alembic, Pydantic v2, PyMySQL, python-jose (JWT), argon2-cffi, slowapi (rate limiting), xgboost 3.1.3, scikit-learn 1.6.1, tensorflow 2.20/keras 3.12, shap (optional), pytest + httpx.

**Spec:** `docs/superpowers/specs/2026-11-03-claims-management-system-design.md` (read it alongside this plan; this plan argues from it).

## Global Constraints

- API versioned under `/api/v1`; Swagger at `/docs`.
- Backend lives in `backend/` beside `frontend/`. Folder layout follows brief §3 exactly.
- Passwords hashed with **Argon2id** (`argon2-cffi`); never stored or logged in plaintext.
- DB credentials read from `backend/.env` only; `.env` is git-ignored; `.env.example` committed with placeholder values. Never hardcode secrets; never send secrets to the client.
- DB name `claims_database`, host `localhost`, port `3306`, user `root`, password from env `DB_PASSWORD`.
- **No notification table, model, schema, service, route, or record anywhere.**
- RBAC + ownership/assignment are enforced **server-side**; role and user identity come only from the validated JWT, never from request bodies or query params.
- All DB access via SQLAlchemy (parameterized); no raw string-interpolated SQL.
- CORS allows only the Next.js origin (`http://localhost:3000`), `allow_credentials=True`.
- Canonical claim statuses (exact strings): `Submitted`, `Under Review`, `Action Required`, `Agent-Verified`, `Fraud Review`, `Approved`, `Rejected`, `Disputed`, `Revaluation`.
- Roles (exact strings): `client`, `agent`, `manager`.
- ML is advisory only; no endpoint auto-sets a claim to Rejected/Approved from a model output.
- XGBoost review threshold is `0.32083502411842346` (from `model_metadata.json`); do not hardcode a different value — load it from the metadata file.

## Review Focus

- **Cross-user claim access:** `GET/PUT /claims/{id}` and document download for a claim the caller neither owns nor is assigned to must return 403/404, not the claim. (Tested in Tasks 8 & 11.)
- **Illegal status transitions:** e.g. client moving a claim straight to `Approved`, or agent approving — must 409/403 and leave status unchanged. (Tested in Task 8.)
- **Privilege escalation via register:** `POST /auth/register` with `role: "manager"` in the body must still create a `client`. (Tested in Task 4.)
- **Malicious upload:** wrong MIME/extension, oversized file, and `../` path-traversal filename must be rejected; stored name must be server-generated. (Tested in Task 11.)
- **Missing ML model file:** when a model file is absent/unloadable, `/ml/predict` returns `model_status: "OFFLINE"` with HTTP 200 and no stack trace. (Tested in Task 12.)
